## Objective

1. Display a full-size window that says "Media Organizer".
2. Display a button in the middle that says "Choose Ingestion Folder"
3. Open a file chooser to get a handle to a file

## Addressing 1 

- The first place I'd look to understand sizing options is the "WindowBuilder" part of the GTK crate. Since this follows the typical Rust "Builder" pattern, I can probably just set the Window width/height with a builder method, maybe grabbing the display width/height via an OS crate if needed
  - Even simpler, the WindowBuilder class has "fullscreened", a method which calls the relevant method from the GtkWindowExt underlying class

- Calling "fullscreened" worked, but now there's a problem with troubleshooting this - how do we exit? We lost the very nice menu buttons.
  - Maybe there's a method for addressing this in WindowBuilder as well, it's an extremely common issue to face.
  - Really what I wanted before was "maximized", not "fullscreened" - this isn't really a fullscreen application like a video game, we still want system menus and whatnot. "maximized" gets us what we want - a full width/height window with a delete button and everything.

## Addressing 2 

- Displaying the button is simple, but is there really a way to get it in the middle? This would likely be a property of the box itself, so I would start by looking at GtkBox.
  - So, these elements are sized somewhat similarly to how they would be with CSS. We set the "vexpand" and "hexpand" methods to expand the vertical and horizontal spaces, respectively. We set them on both the button and the box; the Button will take up the available space in the Box to center itself, but the Box must also take up the full height/width of the Window to get the desired look.

## Addressing 3 
- I'm going to guess GTK does not have a FileHandler functionality or something similar, but I'll take a quick look through to see if I'm wrong. I might need another crate to interface, but this is also probably common enough to have an implementation in GTK.
  - FileDialogBuilder looks promising!
  - FileDIalogBuilder was indeed promising, and got exactly what we needed. This was an important section, as utilizing this properly required reading extensive documentation and utilizing some Rust specific idiosyncracies. In particular, utilizing constructs like "Some" and "Option::None" as well as several closures is very "Rusty" and serves as a reminder that many types work by being wrapped with these options and utilizing pattern matching. The "if let OK/Some" syntax was also used here to actually set the file to the result of the function, which is a common construct we use to do error checking, conditional logic, and assignment at the same time.
